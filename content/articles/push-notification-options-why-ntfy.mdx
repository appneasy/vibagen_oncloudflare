วันที่ 31 มีนาคม 2568 **LINE Notify ปิดตัวถาวร** — service ที่หลายทีมไทยใช้ยิงแจ้งเตือนเข้าไลน์แบบง่าย ๆ (server ยิง 1 request → เด้งเข้ากลุ่ม) หายไปในคืนเดียว

คำถามที่ตามมาคือ: **แล้วเราจะแจ้งเตือนงานเข้ามือถือทีมยังไง** — เครื่องจักรเสีย, มีใบแจ้งซ่อมใหม่, PM เจอค่าผิดปกติ, สต็อกอะไหล่ใกล้หมด — ให้เด้งขึ้นจอมือถือหัวหน้างานทันที โดย **ไม่ต้องจ่ายรายเดือน ไม่ผูกกับเจ้าไหน และคุมข้อมูลเองได้**

บทความนี้เล่าจากงานจริง — เราเจอโจทย์นี้ตอนทำระบบซ่อมบำรุงโรงงาน (OP Chipwood) แล้วสำรวจทางเลือกทั้งหมด ก่อนจะลงเอยที่ตัวที่ชื่อ **ntfy** และ self-host มันเองบน VPS ที่มีอยู่แล้ว

## แจ้งเตือนเข้ามือถือ ทำได้กี่แบบ

โจทย์เดียวกัน — "server อยากบอกอะไรบางอย่าง ให้เด้งเข้ามือถือคน" — มีทางทำหลายทาง แต่ละทางเหมาะกับบริบทต่างกัน:

| แนวทาง | รูปแบบ | คนรับต้องมีอะไร | ค่าใช้จ่าย |
|---|---|---|---|
| **LINE Messaging API** (OA) | push ผ่าน LINE Official Account | แอป LINE + แอดเพจเป็นเพื่อน | ฟรีมี quota (เกินโควตาจ่ายราย msg) |
| **Telegram Bot** | bot ยิงเข้ากลุ่ม/แชท | แอป Telegram | ฟรี ไม่จำกัด |
| **Email / SMS** | ส่งเมล/ข้อความ | อีเมล / เบอร์โทร | เมลฟรี · SMS จ่ายต่อข้อความ |
| **Web Push (Browser)** | แจ้งเตือนผ่านเบราว์เซอร์ | เปิดเว็บแล้วกด allow | ฟรี (แต่ต้องเปิดเว็บ/PWA) |
| **ntfy** | pub-sub topic ยิง HTTP | แอป ntfy (หรือเว็บ) | ฟรี (public) / host เองบน VPS |

ทุกตัว "ทำงานได้" หมด — แต่พอเอามาจับกับโจทย์ **แจ้งเตือนภายในทีม/ระบบหลังบ้าน** ข้อแตกต่างเริ่มสำคัญ

## ntfy ต่างจาก LINE / Telegram ตรงไหน

**ntfy** (อ่านว่า "notify") เป็น open-source pub-sub notification — server ยิง HTTP request 1 ครั้ง เข้า "topic" หนึ่ง แล้วทุกคนที่ subscribe topic นั้นได้รับแจ้งเตือนเด้งขึ้นจอมือถือ แนวคิดเหมือน LINE Notify เดิมเป๊ะ แต่**เป็นของเรา host เองได้**

### 1. เจ้าของข้อมูล vs ฝากบ้านคนอื่น

- **LINE / Telegram** — ข้อความวิ่งผ่าน server ของ LINE (ญี่ปุ่น) / Telegram (ต่างประเทศ) ทั้งหมด เราควบคุมไม่ได้ว่าเก็บอะไร นานแค่ไหน และถ้าวันหนึ่งเขาเปลี่ยนนโยบาย/ปิด service (แบบ LINE Notify) เราทำอะไรไม่ได้
- **ntfy (self-host)** — ยิงเข้า server ของเราเอง (`notify.บริษัท.com`) ข้อมูลอยู่บ้านเรา ไม่มีใครมาปิดได้ ไม่มี vendor lock-in

### 2. คนรับไม่ต้องมีบัญชี / ไม่ต้องแอดเพื่อน

- **LINE** — ผู้รับต้องแอด OA เป็นเพื่อนก่อน (มี friction — บางคนไม่ยอมแอด, บล็อกทีหลัง)
- **Telegram** — ต้องมีบัญชี Telegram (คนไทยหลายคนไม่มี/ไม่คุ้น)
- **ntfy** — subscribe แค่ topic ก็รับได้เลย ไม่ต้องสมัครบัญชีกลาง (ถ้าเปิด public topic) — เหมาะกับ "แจ้งทั่วไปในทีม"

### 3. ไม่มี quota / ไม่มีค่าต่อข้อความ

- **LINE OA** — free tier จำกัดจำนวน push/เดือน เกินแล้วจ่ายรายข้อความ ระบบที่ยิงแจ้งเตือนถี่ ๆ (ทุกใบแจ้งซ่อม, ทุก PM) โดนเพดานเร็ว
- **ntfy self-host** — ยิงกี่หมื่นข้อความก็ได้ ต้นทุนเท่าเดิม (ค่า VPS ที่จ่ายอยู่แล้ว)

### 4. แต่ ntfy ก็มีข้อแลก — ต้องยอมรับ

- ผู้รับต้อง**ลงแอป ntfy** (ไม่ได้อยู่ในมือทุกคนเหมือน LINE ที่คนไทยมีอยู่แล้ว) → เหมาะกับ **แจ้งเตือนภายในทีม/พนักงาน** มากกว่าแจ้งลูกค้าทั่วไป
- ต้อง**ดูแล server เอง** (แต่เป็น Docker container ตัวเดียว — เบามาก)
- self-host ไม่ push background เองบนมือถือ → ต้องพึ่ง relay ของ ntfy.sh ปลุก FCM/APNs (ตั้งค่าบรรทัดเดียว)

> **สรุปการเลือก:** แจ้ง**ลูกค้า**ที่มี LINE อยู่แล้ว → LINE OA ยังดีสุด (rich message + คนไทยมีแอป) · แจ้ง**ทีมงาน/ระบบหลังบ้าน**ที่ยิงถี่และหวงข้อมูล → **ntfy self-host** คุ้มกว่ามาก · เราเลยใช้ **ทั้งคู่** — LINE คุยกับคนนอก, ntfy แจ้งทีมใน

## ntfy ใช้ได้ 3 แบบ — เลือกตามความพร้อม

ข้อดีอีกอย่างของ ntfy คือมันไม่บังคับให้เราลง server เองตั้งแต่วันแรก — เริ่มจากฟรีก่อน แล้วค่อยขยับได้ตามงาน:

| | **1. ntfy.sh ฟรี** | **2. ntfy.sh Supporter** | **3. Self-host (open-source)** |
|---|---|---|---|
| ค่าใช้จ่าย | ฟรี ไม่ต้องสมัคร | ~$5/เดือน (รายปี) · $6 รายเดือน | ฟรี — จ่ายแค่ค่า VPS ที่มักมีอยู่แล้ว |
| ใครดูแล server | ntfy ดูแลให้ | ntfy ดูแลให้ | **เราดูแลเอง** |
| จอง/คุมสิทธิ์ topic | ❌ topic เป็น public (ใครรู้ชื่อก็อ่าน/ยิงได้) | ✅ จองได้ 3 topic | ✅ **ไม่จำกัด** + ACL เต็ม (deny-all, user, token) |
| ข้อความ/วัน | จำกัด (rate limit) | 2,500 | **ไม่จำกัด** (เท่าที่ server ไหว) |
| Attachment | 15MB · หมดอายุ 3 ชม. | 25MB | ตั้งเอง |
| โดเมนของเรา | ❌ `ntfy.sh/...` | ❌ `ntfy.sh/...` | ✅ `notify.บริษัท.com` |
| เจ้าของข้อมูล | ntfy | ntfy | ✅ **เราเอง 100%** |

> แพ็กสูงกว่านั้น: **Pro ~$10-12/เดือน** (20,000 ข้อความ/วัน · 10 reserved topic) · **Business ~$20-25/เดือน** (50,000 · 50 reserved)

### แล้วควรเลือกแบบไหน

- **แค่อยากลอง / งานส่วนตัว** → `ntfy.sh` ฟรี พอ (รับได้ว่า topic เป็นสาธารณะ ตั้งชื่อเดายาก ๆ)
- **อยากได้ private + ไม่อยากดูแล server** → Supporter $5/เดือน จอง topic ล็อกกับบัญชีเรา จบ
- **งานจริงจังในองค์กร / หลาย project / หวงข้อมูล** → **self-host** คุ้มสุด

**ทำไม self-host ถึงคุ้มสำหรับงานองค์กร:** ได้ topic ไม่จำกัด + ACL เต็ม (deny-all + token ต่อ project — project A ยิงข้ามไป project B ไม่ได้) + โดเมนแบรนด์เราเอง + เป็นเจ้าของข้อมูล 100% และที่สำคัญ **VPS ที่รันมันส่วนใหญ่เรามีอยู่แล้ว** (รันเว็บ/แอปอื่นอยู่) เพิ่ม ntfy container ตัวเดียวแทบไม่กินทรัพยากร → **ต้นทุนส่วนเพิ่มแทบเป็นศูนย์** และกลายเป็น "service กลาง" ให้ทุก project ยิงเข้าตัวเดียวกัน

> ข้อแลกของ self-host: ต้องดูแล server เอง (แต่เบามาก) และตั้ง `upstream-base-url` ให้ push ขึ้นจอมือถือได้ — รายละเอียดวิธีทำอยู่ในบทความคู่กัน

## แล้วเอาไปใช้จริงยังไง (ตัวอย่างจากระบบซ่อมบำรุง)

พอมี ntfy กลางแล้ว การเสียบเข้าระบบง่ายมาก — server ยิง HTTP 1 ครั้ง:

```bash
curl -H "Authorization: Bearer tk_xxx" \
     -d '{
       "topic": "chipwood_alerts",
       "title": "🔧 มีงานซ่อมใหม่",
       "message": "แตะเพื่อดูรายละเอียด",
       "priority": 4,
       "click": "https://chipwood.บริษัท.com/work-orders/123"
     }' \
     https://notify.บริษัท.com
```

พอมีใบแจ้งซ่อมใหม่ / PM เจอค่าผิดปกติ → เด้งเข้ามือถือหัวหน้าช่างทันที แตะแล้วเปิดเข้าแอปตรงงานนั้น

สังเกตว่า message เป็นข้อความ **generic** ("แตะเพื่อดูรายละเอียด") ไม่ใส่ข้อมูลจริง — เพราะแจ้งเตือนเป็น plaintext บน server เรื่อง**ความปลอดภัยตรงนี้มีรายละเอียดที่ต้องคิด** เราแยกไปเล่าละเอียดในบทความคู่กัน

## สรุป

LINE Notify ปิดตัวไม่ใช่จุดจบ — มันเปิดโอกาสให้เรากลับมาถามว่า *"จริง ๆ แล้วเราอยากได้อะไรจากระบบแจ้งเตือน"* คำตอบสำหรับงานภายในทีมคือ: ยืดหยุ่น, คุมข้อมูลเอง, ไม่ผูกกับใคร — และ **ntfy ให้เลือกได้ตั้งแต่ฟรี ($0), จ่ายรายเดือน ($5), ไปจนถึง host เองแบบ unlimited** ตามความพร้อมของแต่ละคน

ไม่ใช่ว่า ntfy ดีกว่า LINE/Telegram ในทุกเรื่อง — มันคนละงาน LINE ไว้คุยกับลูกค้า, ntfy ไว้แจ้งทีมหลังบ้าน — แต่สำหรับโจทย์ที่ LINE Notify เคยทำ **ntfy คือตัวแทนที่ดีกว่าเดิม** เพราะครั้งนี้ไม่มีใครมาปิดมันได้อีก
